# Add — every Code Addiction output lives on the `codeadd-docs` branch

**Date:** 2026-11-11 · **Type:** add · **Plan:** `2026-11-11T121728-PLAN--docs-branch` · **Release:** minor (v1.9.0), tagged by `add-framework--release`

## Summary

Every document a command writes now lives under `.codeadd/docs/`, a git worktree of the orphan branch `codeadd-docs`
in the project's own remote. Docs no longer ride in a code PR and no branch carries its own stale copy. There is no flag
and no fallback; a guard test (`docs-no-legacy`) fails on any tracked file that names the previous location, apart from the
migration command, its test and its fixtures.

## What shipped

- **One resolver.** `docs-root.cjs` owns the root, the branch, the layout, and the doc format version (`DOC_SCHEMA_VERSION`, `docSchemaOf`).
- **The git side.** `docs-branch.cjs` prepares the worktree (`ready`, `created`, `linked`, `missing`), commits it and pushes it. `status.cjs` calls it and prints one `DOCS=` line; `codeadd install` and `update` call it too and take the worktree out and back around an update; `uninstall` commits it and never deletes the branch.
- **Code worktrees** see the same docs through a link (`build-setup.cjs --worktree`); the docs are not copied.
- **`docs-guard`.** At close-out `done.cjs` silently files a misplaced output under the docs root. It never touches the framework's own files.
- **The delivery index** records `code_sha` and `pr`; `touched` reads them. `done.cjs --cleanup` re-stamps the entry with the proven merge commit, then commits and pushes `codeadd-docs`.
- **`codeadd docs migrate [--dry-run]`** moves a legacy project, stages the code-side deletions without committing them, and ends by printing a ready-to-paste prompt (from `templates/docs-migrate-prompt.md`) for the user's own agent. It runs no agent and stamps nothing.
- **`schema:` on every generated document** (and `v` on each JSONL line): `{{doc-schema}}` is a build variable resolved from `DOC_SCHEMA_VERSION`; six new document types are registered in `mcp/types.mjs`.
- **This repository** runs on its own `codeadd-docs` branch; its plans, brainstorming and evidence stay untracked there, deliveries, changelog and the index are tracked.

## Needs your attention

- `add-qa-setup`'s contract shape changed on purpose (the QA run-output ignore moved to the docs branch): every QA user re-runs `/add-qa-setup`.
- The release workflow now builds with `node scripts/build.js --package`, which resolves `{{doc-schema}}` in the trees that ship unbuilt.
- A project with no `origin` remote has no docs root until one is added (`DOCS=missing`).
- Four cli tests fail on `main` too (graph-mcp history, mcp-engine history, inventory L3.6, mcp-packaging gitignore); this delivery did not change them.
