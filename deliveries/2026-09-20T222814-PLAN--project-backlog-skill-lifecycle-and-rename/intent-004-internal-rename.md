## Decided

- Subtopic 004 of the set whose umbrella is
  `docs/brainstorming/2026-09-20T104517-project-backlog-000-umbrella.md`. The umbrella's objective is
  copied verbatim into the design; this subtopic serves it by making the two names match. It depends
  on nothing and can be delivered at any point in the set.
- **Discovery was re-run against `origin/main` after PR #79 (the workbench layer) landed.** The first
  pass of this document targeted `.claude/`, which is now gitignored build output. Every path below is
  from the current tree.

| From | To |
|---|---|
| `workbench/commands/add-framework--roadmap.md` | `workbench/commands/add-framework--backlog.md` |
| `workbench/provider-map.json` key `add-framework--roadmap` | key `add-framework--backlog`, description reworded |
| `docs/roadmap/index.md` | `docs/backlog/index.md` |
| node `internal/command/add-framework--roadmap` | `internal/command/add-framework--backlog` |

- **`git mv` on both files**, never delete-and-create. The file's own header names `git log` on itself
  as where a removed item's text lives, so its history is load-bearing.
- **Both `git log` citations inside the file become `git log --follow`**, and so does the header's
  generic claim. Measured on this repository: plain `git log` on a renamed file returns 2 commits
  where `--follow` returns 6. Renaming the file while leaving the citation bare hands the reader a
  command that silently stops at the rename.
- **No item is renumbered, reworded or reordered.** Items 1.2, 1.4 and §5 come out byte-identical
  except for the word "roadmap" in their own text and the two `--follow` additions. Five months of
  changelogs address them by number.
- **The format stays markdown. The two layers match in name and deliberately not in format.** The
  internal file is read raw by a human and by `/add-framework--plan`; JSONL would end that for a
  migration nobody asked for. Recorded as a decision so a later reader does not "finish" the parity.
- **Nothing under `.claude/` or `.opencode/` is touched by hand.** They are generated by
  `node scripts/build-workbench.js` and gitignored; the build is run and they follow.
  `web/public/artefact-graph.mmd` is tracked but written by `scripts/graph.js` — it regenerates too.
- **`cli/tests/review-no-loops.test.js` L3.5 is the one gate the rename breaks.** It hard-codes
  `'add-framework--roadmap'` at line 383 and asserts a `CLAUDE.md` row for it. Updated **in the same
  commit** as the rename.
- `cli/tests/close-out-hardening.test.js` L264 and `cli/tests/build-artefact-graph.test.js`
  L885–886 / L975–980 name the command in **comments only**. Updated for accuracy; nothing breaks.
- **`CLAUDE.md` line 86 is swept by hand, as a named step.** It is not a node and no build gate reads
  it.
- **One product-layer sentence is corrected**, and it is the entire cross-layer surface:
  `framwork/.codeadd/skills/add-doc-schemas/references/backlog.md` line 71 explains the missing
  `scope` field by contrasting it with "the framework's own roadmap". After the rename that contrast
  names nothing. It names neither the old command nor the old path, so the grep sweep would miss it —
  which is why it is listed rather than swept.
- **`workbench/agents/readme-analyzer.md` line 24 is read and deliberately left alone.** Its "Roadmap"
  is a `README.md` heading, not this file.
- **Delivered changelogs, `docs/delivered.jsonl` and `docs/deliveries/` are not edited.** They record
  what was true, and the item numbers they cite still resolve.
- The renamed command declares the same single `uses:` edge it has today —
  `USES_SKILL → internal/skill/add-final-report`.
- A grep sweep closes the delivery, proving nothing live still names the old command or the old path.
- Out of scope: any change to what the command does, to the file's format or numbering, to the
  question of whether the command should be a skill (settled by plan `2026-09-16T170340`), or to any
  other product-layer file.
