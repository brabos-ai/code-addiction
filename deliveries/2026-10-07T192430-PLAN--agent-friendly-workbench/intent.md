## Decided
- Path architectural — adds a versioned output contract, a new script, a new config file and a new flag others depend on
- Result block opt-in; default `prose` prints exactly today's report — given by the user
- Precedence: `CODEADD_OUTPUT` env > `output.mode` in `workbench/settings.json` > `prose`; invalid value skipped with a warning; resolver failure falls to `prose`
- `json` prints only the block; `both` prints the report then the block — a parser must not skip text
- Schema + emission rule owned only by `add-final-report` (+ `references/result-block.md`); fence `codeadd-result`, `v: 1`, every key always present, `null` for unknown
- Block also emitted at early stops and waits, via one pointer line per `add-framework--*` artefact
- Mode resolved by `node scripts/output-mode.js` (`OUTPUT_MODE=` line) — testable, identical across providers
- Repo config is a new tracked `workbench/settings.json` (JSON — root takes no dependency)
- Fix track is `--fix <slug> [--ticket <id>]` on `add-framework--done`, not a new command — steps 2.3–9 reused
- `--fix` with a `[plan]` argument is refused; without `--fix` done is unchanged
- Fix record `docs/plans/<ts>-FIX--<slug>.md`, generated by done from git + CI facts, never hand-written
- Fix `id` resolved index → `docs/deliveries/` → local record before allocating — no duplicate entries
- Gate 2.2 replaced by the fix gate; 2.3 CI is the validation; 2.4 recovery unavailable for fixes
- Archive member `fix.md` replaces `plan.md` + `ledger.md`; `gh pr merge --merge` kept
- Ticket only via explicit `--ticket`; The Ticket's rules apply unchanged to the fix record
- Out of scope: all of 0029B, the product `add--final-report`, retro-indexing PR #112
