## Decided

1. Problem: five skills in `framwork/.codeadd/skills/` are generic, not part of the Code Addiction flow, and no command or agent loads them: `add--stripe` (~460K), `add--plan-based-features`, `add--optimizing-git-workflow`, `add--project-scaffolding`, `add--skill-creator` (~208K). They ship to every install and widen the surface without serving the framework. Verified on main `dfe98bb0` (v1.5.13).
2. Scope in: delete the five skill folders; remove their keys in `framwork/provider-map.json:120,121,124,130,131`; fix every live reference listed below. Scope out: `add--ux-design` slimming (card `ux-design-core-slim`), dev-skill agnosticism (`agnostic-dev-skills`), greenfield guidance (`brainstorm-greenfield`). No rename of any remaining skill.
3. `add--ecosystem/SKILL.md`: drop the `mention:` rows at :35, :36, :39, :46, :47 and the Skills table rows at :174, :175, :177, :185, :186. Rewrite :115 ("Not for authoring new skills/commands → use `add--skill-creator`") to point to the native Claude Code `skill-creator` plugin. Keep every row `mention:` (catalogue rule, `workbench/commands/add-framework--sync.md:170-182`).
4. Skills that cite a removed skill: `add--backend-development/SKILL.md:13,35`, `add--backend-architecture/SKILL.md:12,26`, `add--frontend-architecture/SKILL.md:11,153` (all `add--project-scaffolding`): remove the `mention:` and the "use add--project-scaffolding" line (the out-of-scope bullet stays, without a pointer). `add--agents-md-style/SKILL.md:13,29` (`add--skill-creator`): remove the `mention:`; :29 keeps `add--token-efficiency` only.
5. Web docs: remove the five entries in `web/src/pages/docs.astro:566,569,571,573,580` (stripe, project-scaffolding, plan-based-features, optimizing-git-workflow, skill-creator).
6. Tests: `cli/tests/graph-query.test.js:271-287` uses `add--stripe` as the depth-1 leaf; swap it for another product skill that the regenerated graph shows with 0 depth-1 dependants (pick it with `node scripts/graph.js impact`, do not guess) and update the comment at :271. `cli/tests/build-artefact-graph.test.js:320` uses `add--skill-creator` only as a string in a synthetic source; swap to a neutral name for clarity. Do NOT touch the legacy-orphan path `skills/add-skill-creator/render-graphs.js` in `cli/src/migrations.js:17`, `scripts/build.js:1792`, `cli/tests/updater.test.js:485`, `cli/tests/install.e2e.test.js:654`, `cli/tests/migrations.test.js:179` — that is the old single-dash layout cleanup and must keep working for old installs. `scripts/build.js:833` is a doc comment example; update the name only if it reads stale.
7. Graph: `framwork/.codeadd/artefact-graph.json` is a build output, not tracked in git; it is regenerated by `npm run build` (`scripts/build.js:2509-2515`, gated by `assertArtefactGraph`). `cli/tests/fixtures/slot-membership-map-v2.json` contains none of the five skills and is a frozen snapshot — no regeneration needed.
8. Workbench: `workbench/skills/add-framework-development/SKILL.md:219` cites `add--skill-creator` as the source of the `references/` convention and lists it as an example; :221 lists `add-stripe` among legacy flat skills. Rewrite :219 to state the convention directly and add the instruction to install the native plugin: in Claude Code run `/plugin install skill-creator@claude-plugins-official` (if the marketplace is missing: `/plugin marketplace add anthropics/claude-plugins-official`; shell form: `claude plugin install skill-creator@claude-plugins-official`). Remove `add-stripe` from :221. `workbench/skills/add-framework-product-layer/SKILL.md:41` ("`add-skill-creator/SKILL.md` IF the artefact is a skill") → point to the native skill-creator plugin plus `add-framework-development`. `workbench/commands/add-framework--sync.md:180` uses `add-stripe` as a historical example → reword to "a leaf skill".
9. No migration script: `pruneObsolete` (`cli/src/release-copy.js:101`, called by `cli/src/updater.js:105`, `cli/src/installer.js:360`, `cli/src/modify.js:237`) deletes every file in the prior manifest that the new release does not write; skills are not matched by `PRESERVE_PATTERNS` (`release-copy.js:17`).
10. Release note: warn that `codeadd update` removes the five skills, and point skill authors to the native `skill-creator` plugin.
11. Target: next release.
12. Acceptance criteria: (a) the five folders are gone and `npm run build` passes, with no skill of those names in the build output or `artefact-graph.json`; (b) `rg --hidden` for the five names in `framwork/ cli/src web/ workbench/` returns only the legacy-orphan path from decision 6; (c) `npm run test:all` passes, with the graph-query leaf test using a real leaf; (d) the workbench names the native install command; (e) the release note carries the warning.
13. Risks: users who relied on `add--stripe` (or the other four) lose it silently on `update` → release note (decision 10). Local edits inside those skill folders are also deleted by `pruneObsolete`, same note. `pruneObsolete` unlinks files only, so empty skill folders may remain after `update`; harmless, not fixed here.
