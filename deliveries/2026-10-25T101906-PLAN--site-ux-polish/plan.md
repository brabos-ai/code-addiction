## Objective

[from conversation, no design document]
The public site (landing and the single docs page under `web/`) renders its brand fonts, does not scroll
sideways on a phone, is fully usable by keyboard and under reduced motion, shows graphs generated from the
build sidecar with no internal workbench node, and offers docs search, a terminal demo and a few
reduced-motion-safe effects.

**When this build is done:** every finding the intent file's Decided list carries is fixed or added on
`main`, each bug fix is pinned by a test that failed before it, `web/public/artefact-graph.mmd` and
`web/public/ecosystem.json` are both regenerated by one `scripts/graph.js` call each and held current by a
test, and `/add-framework--sync` still knows where providers, commands and the two graphs live.

**Ticket done when:** At 390 px both pages have scrollWidth 390; h1 renders Syne and code renders JetBrains Mono, self-hosted; every control has a visible focus ring and works by keyboard; reduced motion disables all animation; the ecosystem map and artefact graph are generated and list no add-framework--* node; Pagefind search works; Lighthouse accessibility >= 95 and CLS <= 0.1; web build green.

internal `add-framework--*` nodes in the public Mermaid graph, and no docs navigation aids. Maicon approved

## Problem

1. **Brand fonts never render** — `web/src/styles/global.css` declares `--font-family-display/-body/-mono` inside `@theme`; Tailwind v4 reads `--font-*`. `web/tailwind.config.mjs` is v3 syntax and never loaded. Fonts arrive through a chained Google `@import` (P1.1, P3.1).
2. **Both pages scroll sideways on a phone** — home grows to 495 px and docs to 561 px at a 390 px viewport (P1.2, P1.3). WCAG 1.4.10 Reflow fails.
3. **Keyboard and motion users are not served** — no visible focus ring, the hero install copy is a clickable `div`, small text below AA, no reduced-motion handling, hero text starts at `opacity:0` (P1.4–P1.7).
4. **Content disagrees with itself** — 7 provider tiles for "six providers" with Codex twice and a ZCode mismatch, mixed-language accessible names, a nav label pointing at the wrong section, no share preview (P2.3, P2.7, P2.8).
5. **The graphs are wrong** — the Mermaid graph lists 3 internal `add-framework--*` commands users cannot install; the Ecosystem Map is a ~500-line hand-written literal showing 29 skills and 17 agents against a shipped 42 and 22 (P2.1, P2.2).
6. **The docs page has no way to find things** — no scroll-spy, sidebar order differs from page order, no search, mobile menus without state or Esc (P2.4, P2.5, §4).

## Proposal

Five phases on one branch, each leaving the site building green. Phase A fixes what every visitor sees and
what blocks keyboard and motion users. Phase B makes the content true and single-sourced. Phase C moves both
graphs to generated files behind `scripts/graph.js`. Phase D adds search, the demo and the effects, with the
page transition last because it is the change most likely to break existing inline scripts. Phase E points
`/add-framework--sync` and its analyzers at the new component, data file and generated graphs, so the next
release sync does not miss content that moved.

Static-source assertions live in a new `scripts/tests/web-site.test.cjs` (a native `node:test` suite, like
the rest of `scripts/tests/`, reading `web/` source the way `graph-mermaid.test.js` already reads
`docs.astro`). The two graph F-blocks (F12, F13) are tagged `[product]` because their tests live in
`cli/tests/`, which the layer table puts on the product side. Rendered behaviour — computed fonts, `scrollWidth`, focus, reduced
motion, search, Lighthouse — is proven on `npm --prefix web run preview` with a headless browser and recorded
in the ledger.

**Discipline: RED first.** For every F-block marked "bug" the build writes its L1 case, runs it, records the
