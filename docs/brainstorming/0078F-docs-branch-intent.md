## Decided

1. Problem: every Code Addiction output is written into the user's code branch under `docs/` (and `.codeadd/project/decisions.jsonl`), so docs ride along in every PR and every branch carries its own stale copy. There is no central path: `docs/` is hardcoded in 375 places across 83 files (commands 156/13 files, skills 113/35, scripts 61/13, agents 12/4, fragments 12/7, agent-mode 12/3, plugins 6/5, fallbacks 2/2), plus duplicated constants in `scripts/build-setup.cjs:59`, `scripts/feature-id.cjs:40`, `scripts/init.cjs:49`, `scripts/status.cjs:69`, `scripts/migrate-ids.cjs:42-43`, `scripts/done.cjs:236-241` (`CLOSE_OUT_PATHS`), `scripts/delivery-index-core.cjs:106,138,490`, `scripts/qa-evidence.cjs:502`, `scripts/get-branch-metadata.cjs:107`, and outside the product `mcp/corpora.mjs:605` (`roots: ['docs', '.codeadd/wiki']`).
2. Storage: an orphan branch `codeadd-docs` in the project's own remote, checked out as a git worktree at `.codeadd/docs/` in the primary checkout. It is already ignored by the `.codeadd/*` line written by `cli/src/gitignore.js` (no new ignore line). The branch root holds today's `docs/` layout (`features/<id>-<slug>/`, `brainstorm/`, `diagnose/`, `audit(s)/`, `health-checks/`, `delivered.jsonl`, `design-system.md`, `code-quality-review.md`, ...) plus `decisions.jsonl` (moved from `.codeadd/project/decisions.jsonl`).
3. Not optional, zero legacy (Maicon, 2026-11-11, "não quero nada legado com relação ao path anterior"): no feature flag, no fallback, no compatibility route, no "if the old path exists" logic, and no mention of the old `docs/` location anywhere in the product. This covers code and scripts (`framwork/.codeadd/scripts/`, `cli/src/`, `mcp/`), every agent instruction (commands, skills, agents, fragments, agent-mode, plugins, fallbacks, templates) and the product README/docs (README, `cli/README.md`, the docs site), apart from decision 14. Every Code Addiction output is always written under `.codeadd/docs/`. A command or script that cannot resolve the docs worktree prepares it (decision 7) or fails with an explicit error. The only exception is the optional migrate command and its short guide (decision 14): they alone know the legacy source paths. Shipped tests that name the old paths exist only as fixtures for the migrate command.
4. One resolver: a single shipped module (e.g. `scripts/docs-root.cjs`) owns the docs root and replaces every duplicated constant in decision 1, including `mcp/corpora.mjs` roots, `delivery-index-core.cjs` and `done.cjs`. Commands, skills, agents, fragments, agent-mode, plugins and fallbacks reference `.codeadd/docs/...` directly or through one build variable; the Engineer picks one in the plan, keeping agent instructions minimal. `skills/add--resource-path-convention/SKILL.md` and `skills/add--doc-schemas/SKILL.md` (doc resolution `grep -rE "^id: ..." docs/`) are updated to the new root.
5. One universal search line in the shared instructions (e.g. `add--doc-schemas` / `AGENTS.md` style block): always pass `.codeadd/docs/` explicitly when searching, because rg/Grep skip gitignored paths (Claude Code Grep, Codex and Cursor all use ripgrep).
6. `.codeadd/wiki/` stays in the code branch (it describes the code at that commit); `.codeadd/settings.json` and `manifest.json` stay where they are.
7. Setup and fresh clones: `scripts/status.cjs` (already run by almost every command) auto-prepares the worktree. If `origin/codeadd-docs` exists and the worktree is missing, it fetches and runs `git worktree add .codeadd/docs codeadd-docs`; if the branch does not exist anywhere, it creates the orphan branch with an empty root commit and pushes it. `codeadd install` / `update` run the same step. `status.cjs` never fails on this; it prints one signal line (e.g. `DOCS=ready|created|missing`) and carries on.
8. Code worktrees: `.worktrees/<feat>` made by `scripts/build-setup.cjs --worktree` get `.codeadd/docs` as a link to the primary checkout's docs worktree (symlink; directory junction on Windows), found via `git rev-parse --git-common-dir`. `copyInstalled` (`build-setup.cjs:149-170`) excludes `.codeadd/docs` from its ignored-file copy. Every code worktree and agent sees the same docs.
9. Commit and push policy (remote, never local-only): each command that writes docs commits in the docs worktree when it ends; push happens at `/add-done` and at the agent-mode handoff. `framwork/.codeadd/agent-mode/README.md:216` changes from "commit intent + `docs/features/` to main before handoff" to "push `codeadd-docs` before handoff". Conflicts are unlikely (different files/folders per feature).
10. Git handling, from the board lessons (`docs/deliveries/2026-10-10T110912-PLAN--board-outside-code-branches/`, `docs/deliveries/2026-10-29T223023-PLAN--remove-board/`): no read-sync, no own lock system, no app. Plain worktree commit/push with retry when `index.lock` is held, fetch + rebase once on a rejected push, `GIT_TERMINAL_PROMPT=0` with a bounded network timeout, `core.autocrlf=false` and a `.gitattributes` with `* text=auto eol=lf` on the branch, git identity fallback for commits.
11. PR: Code Addiction docs are not in the code PR (keeps the PR clean; reviewers open the docs worktree). `/add-pull-request` (`commands/add-pull-request.md`) may add links to `codeadd-docs` paths; Engineer's call, low priority.
12. Detector `docs-guard` (new shipped script, provider-agnostic, no hooks): it runs automatically and silently fixes, no warnings, no blocking. It moves misplaced Code Addiction outputs into their place in the `.codeadd/docs/` layout and removes them from the code branch index. Like everything outside decision 14, it carries no knowledge of the old `docs/` location: its rules are location-agnostic and match anywhere outside `.codeadd/docs/`. It runs in `scripts/done.cjs` before commit-push (replacing the `docs/features` and `docs/delivered.jsonl` entries of `CLOSE_OUT_PATHS`) and may run in `status.cjs`. Detection, over files changed since the merge base plus pending files: (a) `.md` with a frontmatter `type:` registered in `mcp/types.mjs` (18 types: feature, hotfix, prd, brainstorm, brainstorm-intent, audit-report, diagnose-report, setup-receipt, feature-plan, feature-design, epic, review, qa-validation, changelog, tutorial, how-to, reference, explanation); (b) layout and name patterns at any path: a folder named `[0-9]{4}[A-Z]-<slug>` holding Code Addiction files, `iterations.md` (header `# Iterations`), `build-ledger.md` and `tasks.md` (header `# Tasks:`) inside such a folder, `delivered.jsonl`, `decisions.jsonl`, and `YYYY-MM-DDTHHMMSS-<slug>(-intent)?.md` names; (c) JSONL whose lines carry the known keys (`v`/`ts`/`id`/`by` of `delivered.jsonl`, `ts`/`agent`/`type` of `scripts/log-jsonl.cjs`). A user file with no registered type and no matching pattern is never touched.
13. No hooks of any provider (Claude Code, Codex, Cursor, ...). Only scripts and instructions.
14. Legacy migration: an optional, idempotent command (e.g. `codeadd docs migrate`, in `cli/src/` next to `migrations.js`) the user may run. It moves the legacy Code Addiction docs (detected with the decision-12 rules) from the code branch into `codeadd-docs`, with no history preservation: one fresh commit on the docs branch carrying a `Migrated-From: <base sha>` trailer. The code side is `git rm` + staged for user review, never committed or pushed by the command. Re-run answers `MIGRATED=already`. A short migration guide ships with it (`cli/README.md` and the docs site).
15. `delivered.jsonl` contract: `scripts/delivery-index-core.cjs` derives `touched` from the first-parent commit that introduced the entry line and touched code outside `docs/` (`:490-506`). With the index on another branch that link is gone, so `/add-done` records the code commit sha and PR number in the entry, and `touched` reads them instead.
16. Feature id allocation (`scripts/feature-id.cjs`, `init.cjs`, `status.cjs next-id`) scans `.codeadd/docs/features/` through the resolver; the docs branch becomes the single shared source of ids across worktrees and machines.
17. Uninstall/update: `cli/src/uninstaller.js` and the updater run `git worktree remove` (and `git worktree prune`) before touching `.codeadd/`, and never delete the `codeadd-docs` branch.
18. This repo too, in the same delivery: code-addiction's own `docs/` (`docs/deliveries/`, `docs/plans/`, `docs/changelog/`, `docs/delivered.jsonl`) moves to its own `codeadd-docs` branch, and the `workbench/` commands and skills that write them (e.g. `workbench/skills/add-plan-authoring`, `add-framework--done`, `add-framework--build`) use the new root. Public docs that the site or README link stay where the Engineer judges they must.
19. Release: minor (v1.9.0). CHANGELOG, README, `cli/README.md` and the docs site (`web/src/pages/docs.astro`) describe the docs branch, the guard and the migrate command.
20. Migrate prompt (Maicon added to scope, 2026-11-11; PM decided): `codeadd docs migrate` ends by printing a ready-to-paste, provider-agnostic, plain-text prompt for the user's own agent. The prompt asks the agent to review the migrated docs in `.codeadd/docs/`, adjust the legacy docs to the current doc standard (`skills/add--doc-schemas/SKILL.md` and its `references/`), stamp the current schema version (decision 21) on each adjusted file, and report what changed. The prompt text lives in one template file in the product (e.g. under `framwork/.codeadd/templates/`), never hardcoded in several places. The command only prints it; it never runs an agent.
21. Schema version on every generated artifact (Maicon added to scope, 2026-11-11; PM decided):
    - Field: `schema: <integer>` in the YAML frontmatter of every generated markdown artifact, next to `id`/`type`/`created`/`updated`/`related`/`tags`. It starts at `1` in v1.9.0.
    - Source: one constant (e.g. `DOC_SCHEMA_VERSION`) in the docs-root module of decision 4, documented in `skills/add--doc-schemas/SKILL.md` (Universal Document Requirements, mandatory fields). Templates and commands reference it through the same resolver or build variable used for the paths, never as a number hardcoded in many files. It is bumped only when the doc format changes, independent of the package version.
    - Generated markdown with no frontmatter today (`iterations.md` from `scripts/log-iteration.cjs`, `build-ledger.md` from `scripts/build-ledger.cjs`, `tasks.md` per `skills/add--tasks-checklist`, the health-check reports per `skills/add--health-check`, `design-system.md`, `code-quality-review.md`) gains a minimal frontmatter with `type` and `schema`; the new types are registered in `mcp/types.mjs`.
    - JSONL outputs carry a per-line `v`: `delivered.jsonl` already writes `v: 1` (`scripts/delivery-index-core.cjs:219`); `scripts/log-jsonl.cjs` entries gain `v`.
    - A doc without the field is schema `0` (legacy). The migrate command does not stamp the version (it only moves); the printed prompt of decision 20 adjusts and stamps. Future doc migrations key off `schema`.
    - `docs-guard` (decision 12) may also use the presence of `schema:` together with a registered `type:` as a detection signal.
22. Risks to cover in the plan:
    - `touched` derivation (decision 15).
    - Uninstall/update deleting the worktree (decision 17).
    - Rulesets or branch protection with `*` patterns blocking the push to `codeadd-docs`: report the push failure clearly and keep the local commit.
    - Windows: junction instead of symlink, CRLF, long paths.
    - Tools scanning the repo root (jest/vitest, tsc, eslint, prettier, markdown linters, static-site globs) picking up `.codeadd/docs/`: low for md/json only, but check the repo's own test and build globs.
    - Agents not finding docs with rg/Grep (decision 5).
    - `git clean -fdx` removing uncommitted docs (covered by commit at command end, decision 9).
23. Acceptance criteria:
    - A fresh install writes every output to `.codeadd/docs/` on the `codeadd-docs` branch.
    - A fresh clone (and a cloud agent) gets the docs worktree set up automatically by `status.cjs`.
    - Code worktrees made by `build-setup.cjs --worktree` see the same docs through the link, and the docs worktree is not copied.
    - `/add-done` pushes `codeadd-docs`, and the code PR contains no Code Addiction docs.
    - `docs-guard` moves a planted misplaced doc (md with registered type, feature-folder file, JSONL) silently and leaves a user doc alone.
    - The migrate command moves legacy docs, stages the code side and is idempotent.
    - The code-addiction repo itself is migrated.
    - Zero legacy: a grep of `framwork/.codeadd/`, `cli/src/`, `mcp/` and the product README/docs for the old `docs/` output paths (`docs/features`, `docs/brainstorm`, `docs/diagnose`, `docs/audit`, `docs/health-checks`, `docs/delivered.jsonl`, `.codeadd/project/decisions.jsonl`, ...) returns only the migrate command and its guide (and the migrate command's test fixtures). A test guards it.
    - Every artifact generated after install carries `schema: 1` in its frontmatter (or `v` on each JSONL line), including the formerly frontmatter-less files of decision 21.
    - `codeadd docs migrate` prints the agent prompt read from its single template file and runs no agent.
    - A doc without `schema` is recognized as legacy (schema `0`).
    - Native tests pass on Linux and Windows paths.
