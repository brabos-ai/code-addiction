# Board pipeline phase statuses — a ticket moves as the pipeline runs, behind one feature

> **Date:** 2026-09-23
> **Plan:** `docs/plans/2026-09-23T193550-PLAN--board-pipeline-phase-statuses.md`
> **Layer:** both
> **Ticket:** 0005B

A ticket used to be written twice, `doing` at the build and `done` at the close-out. Between those two
writes the board said nothing about where the work stood. This delivery gives each pipeline phase an
entry status and an exit status, and has the commands write them as they run. The board then groups
tickets by phase column and badges each card with its exact status.

Everything that tells a command to write the board lives behind the new `board` feature, which is off by
default. A project that never turns it on carries none of that text. One delivery on one branch, in four
checkpoints.

## Added

- **The phase model** (`backlog.sh` DEFAULT_DEFS, `add-doc-schemas/references/backlog.md`) — nine statuses
  (`open`, `refining`, `shaped`, `planning`, `planned`, `doing`, `in-review`, `done`, `dropped`) over seven
  columns (`backlog`, `shaping`, `planning`, `building`, `review`, `done`, and a hidden `dropped`). Each
  status has four optional keys: `column`, `label`, `means` and `order`. Each key has a declared fallback,
  so a hand-written definitions file with only names still works. The reserved names are a documented
  contract, not enforced in code. An existing definitions file is never rewritten (`DEFS_PRESERVED` stands).
- **A fourteenth ticket field, `feature`** — the `[NNNN]F` id `/add.new` allocates, written in the same
  write as `refining`. It holds an id, never a path. `work_id` stays with `doing`, because the `work_id`
  stop reads it.
- **`add-backlog/references/phases.md`** — the model: what each status and column means. **`lifecycle.md`**
  is rewritten as the procedure: the seven writes, the step each happens at, and the two rules that decide
  whether a write happens. The phase check skips an entry write when the ticket already holds that phase's
  entry or exit status. The `work_id` stop means that once the build has started, only `in-review` and
  `done` are still written. Neither rule compares order.
- **The `board` feature** (`cli/src/features.js`, `default: false`) over six commands: `add.brainstorm`,
  `add.new`, `add.plan`, `add.build`, `add.done` and `add.hotfix`. Each command carries empty marker pairs,
  and `fragments/board/<command>.md` fills them. Every section is an anchor plus a pointer to the
  `lifecycle.md` row, and none restates a rule. The fifteen board instruction sites that used to live
  inside the commands moved out: nine byte-identical, six reworded and reviewed.
- **`add.hotfix` on the board for the first time** — it resolves a ticket id from its own invocation,
  writes `doing` and records `ticket:` in its `about.md` (`fix.md` gains the optional key). It never writes
  `in-review`: a hotfix opens no PR.
- **The internal pipeline follows the same seven writes** (`add-plan-authoring` § The Ticket, and the
  brainstorm, plan and build stages), unconditionally, since the workbench has no feature system.
  `cli/tests/board-phase-writes.test.js` L11.5 holds the internal and product maps equal.
- **The board app** (`board/`) — `/api/board` carries `columns`, plus each status's `column` and `label`.
  The kanban, the phone tabs and the desktop row group by column. Each card carries its own status badge,
  and done or dropped cards are dimmed one by one. `dropped` is hidden unless `?column=dropped` or the
  "Show dropped" toggle asks for it, and that param adds columns rather than replacing them. The skeleton
  shows six columns. The card and the ticket sheet show `feature` beside `work_id`.

## Changed

- **The CLI resolves `{{skill:}}`, `{{cmd:}}` and `{{addpath:}}` in fragments at injection time**
  (`cli/src/injection-core.js`). Before this, every feature and plugin fragment reached an installed
  project with its placeholders raw. Found mid-build and fixed on the user's decision.
- **This repository's `docs/backlog.definitions.json`** now carries the nine statuses and seven columns,
  generated by `backlog.sh` rather than written by hand.
- **`board/e2e` L4.5** — at the 15rem column floor, six columns do not fit a 1080px viewport. The user
  chose to ship them with the row scrolling. The test now asserts that the page never scrolls sideways and
  that every column comes into view along the row. The layout that fits all six is ticket **0008B**.
- **`add-framework-product-layer`** records how to run bats in the container from a worktree, and when a
  one-file run closes a block.

## Not included

No migration and no injection into an existing definitions file. No transition validation, which is what
lets a hotfix jump from `open` to `doing`. No drift signal in `status.sh` for a skipped write. No write
path from the board app. The order bug between the `tdd-pipeline` and `qa-pipeline` `step-list` sections in
`add.plan` predates this delivery and is ticket **0007B**.
