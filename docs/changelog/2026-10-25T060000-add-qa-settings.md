# Add: `.codeadd/settings.json`, the project settings file, with `/add-qa-setup` moved onto it

## Outcome

A project keeps its QA setup in the `qa` section of `.codeadd/settings.json`: the values, the receipt state and an append-only `log`. It is committed to git and nothing is written under `docs/qa/`. `/add-qa-setup` writes that section and checks it with a JSON gate. `qa-preflight.cjs` and `status.cjs` read it and print the same signals as before. Migration `0005-qa-settings` converts a v1.6.0 project on its next `codeadd update` without making it STALE. Ticket 0066B.

## Changes

- New skill `add--settings`: location, ownership (only commands write, each only its own section, read → merge → write), the content rule, the `qa` schema and the receipt fields. `receipt.md` in `add--doc-schemas` is now a pointer to it.
- `/add-qa-setup`: the contract path is `.codeadd/settings.json#qa`, owner `shared`, `changed-in: 1.7.0`; the validation step is a JSON check instead of the markdown gate. All QA readers (fragments, `e2e-agent`, `qa-agent`, `add--qa`, `add--qa-spec`, `add--setup-contract`) point to the new keys.
- `qa-preflight.cjs` and `status.cjs` read `qa.baseUrl` and `qa["setup-shape"]` from the JSON. A malformed file reads as `broken` in `qa-preflight.cjs` and as STALE in `status.cjs`; a file with no `qa` section reads as missing.
- Migration `0005-qa-settings` moves `docs/qa/config.json` and the `qa-setup.md` receipt (Decision Log rows into `qa.log`), rewrites the config path in the generated `qa-project` skill, and deletes the old files. It stamps the new shape only when the recorded one was `sha256:25b937ee17628d6b`, and is idempotent.
- Bug fix: the managed `.gitignore` block no longer ignores `.codeadd/wiki/`, and keeps `.codeadd/settings.json` committable.
- Bug fix: a fresh clone holding only `board.json`, `settings.json` and `wiki/` installs without `--force`.
- Bug fix: an uninstall with a corrupted manifest keeps `board.json`, `settings.json` and `wiki/`.

## Action for installed projects

**Note:** `codeadd update` runs migration `0005` once. It moves your QA config and receipt into `.codeadd/settings.json` and deletes `docs/qa/config.json` and `docs/qa/qa-setup.md`. Commit the new file. If a `qa` section already existed, the migration only adds missing keys and keeps the old files for you to review.

**Note:** `.codeadd/wiki/` is no longer ignored by git. A generated wiki now shows up in `git status`.
