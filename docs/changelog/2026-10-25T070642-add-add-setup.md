# Add: `/add-setup`, a guided onboarding command

## Outcome

After `codeadd install` or `codeadd update`, a user runs `/add-setup`. It checks the project, shows every feature and plugin with its benefit and a yes/no recommendation in one numbered list, and sets up only the items the user accepts. It records each decision and its reason in the `setup` section of `.codeadd/settings.json`, so a later run asks only what is new, changed or named to revisit. Ticket 0067B.

## Changes

- New command `add-setup`, registered for every provider. It reads the project, asks once, then runs in a fixed order: tool installs, one `codeadd modify`, `gitnexus setup` and `gitnexus analyze`, `/add-qa-setup`, a check that the MCP server answers, then `/add-wiki`. A greenfield repo gets no list and is sent to `/add-brainstorm`.
- `add--ecosystem`: a `Benefit` column in `## Features` and `## Plugins` (the one source of benefit text), a Commands row, Used By cells, and routing rows for `codeadd install` and `add-setup`. The `codeadd update` row now points to `/add-setup` first, then `/add-wiki update`.
- `add--settings`: the `setup` section (`setup-shape: "none"`, `offered.<item>` with `enabled | already-on | declined | unavailable | failed`, and an append-only `log`). `"none"` is the one legal non-hash `setup-shape`, only in a section whose command has no contract.
- `/add-qa-setup` and `/add-wiki` take their answers from a `## Setup answers` block when `/add-setup` printed one. The `add-qa-setup` contract shape did not change.
- `/add-help` suggests `/add-setup` and still runs only `codeadd --help`.
- The install outro says `run: /add-setup`; the update outro points to it. The plugin catalog and `AGENTS.md` now say the CLI never installs a tool, while the setup commands may after the user confirms.
- `README.md`, the docs page and the command diagram list `/add-setup`.

## Action for installed projects

**Note:** run `/add-setup` once after `codeadd update`. It adds nothing you do not accept and writes only the `setup` section of `.codeadd/settings.json`. Commit that file if you want teammates to see the decisions.
