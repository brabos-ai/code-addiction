# Brainstorm: Project Backlog 004 — the internal rename

> **Status:** final (ready for /add-framework--plan)
> **Date:** 2026-09-20
> **Type:** rename (internal layer, with one product-layer word)
> **Umbrella:** `docs/brainstorming/2026-09-20T104517-project-backlog-000-umbrella.md`

## Objective

Today a user of the framework has nowhere to record "what to do next" inside their own project. The
idea dies in the chat, or it becomes a full plan far too early. When this is done, a **skill** writes
that intent into a file in the user's repository — with real paths and a check someone can actually
run — so that it still means something weeks later. The internal equivalent is renamed to
`add-framework--backlog` so both names match.

**Serves the objective by** making the two names match, so the internal artefact and the product one
stop describing the same thing under different words.

## Discovery

⛔ **This Discovery was re-run against `origin/main` after the workbench layer landed.** PR #79
(`29a25d0`) moved the internal layer, and a first pass of this document was written against a
checkout 23 commits behind it. Every path below is from the current tree.

- **`workbench/commands/add-framework--roadmap.md`** — **the source file.** 265 lines, nine steps.
  `impact --depth 1` on `internal/command/add-framework--roadmap` returns **zero dependants**; its only
  outbound edge is `USES_SKILL → internal/skill/add-final-report`.
- **`workbench/provider-map.json`** — **a registry the internal layer did not have before PR #79.**
  It carries the key `"add-framework--roadmap"` with a `description` field whose text says "roadmap"
  twice. `CLAUDE.md` now states the rule outright: *"DO NOT edit `.claude/commands/` … DO edit
  `workbench/`, register in `workbench/provider-map.json`, run the workbench build."*
- **`.claude/commands/`, `.claude/skills/`, `.claude/agents/` and `.opencode/`** — **generated output
  and gitignored** (`.gitignore` lines 202–204). `node scripts/build-workbench.js` writes them from
  `workbench/`. Nothing here is renamed by hand; it regenerates.
- **`docs/roadmap/index.md`** — not a node, and **not empty**: it carries live items (1.2, 1.4 and the
  §5 theme among them), each addressed by number in commit messages, changelogs and past
  conversations. Its own header states the rule that governs this subtopic: *"A delivered item is
  removed, never renumbered."*
- **`git log` versus `git log --follow`** — measured on this repository, on a file the workbench move
  renamed: plain `git log <path>` returns **2** commits and `--follow` returns **6**. Plain `git log`
  stops at a rename. This matters because `docs/roadmap/index.md` cites `git log` on itself, twice, as
  where a removed item's text lives.
- **`CLAUDE.md` line 86** — the "Internal commands" table row naming the command and its
  `docs/roadmap/index.md` path. **`CLAUDE.md` is not a node**; `add-artefact-graph` lists it under what
  the graph cannot see, and nothing in either build inspects it.
- **`cli/tests/review-no-loops.test.js` line 383** — hard-codes `'add-framework--roadmap'` in test
  L3.5's list and asserts that `CLAUDE.md` still carries a table row for it. **This is the one gate the
  rename actually breaks.** Found by grep, not by the graph, because `cli/tests/` produce no nodes.
- **`cli/tests/close-out-hardening.test.js` line 264 and `cli/tests/build-artefact-graph.test.js`
  lines 885–886, 975–980** — name the command in **comments only**. Their assertions are about
  `add-framework--done` and about node and edge counts, neither of which a rename changes.
- **`web/public/artefact-graph.mmd`** — tracked, and **generated by `scripts/graph.js`** (its
  `DOCS_DIAGRAM` constant). It holds the node id and regenerates. `web/dist/` is gitignored.
- **`workbench/agents/readme-analyzer.md` line 24** — `| "Roadmap" | Delivered items still listed |`.
  Read in context: it is about a heading in the project `README.md`, not about this file, and
  `README.md` has no such section today.
- **`framwork/.codeadd/skills/add-doc-schemas/references/backlog.md` line 71** — a **product** file
  shipped by 001: *"That field exists on the framework's own roadmap because that repository has two
  layers."* It names neither the old command nor the old path, so a grep sweep for either would miss
  it, and after this rename the sentence distinguishes nothing by name.
- **Plan `2026-09-16T170340-PLAN--the-pipeline-chains`** — explicitly excluded `--roadmap` from the
  command-to-skill conversion: it stays a standalone command, not a pipeline stage. This rename does
  not reopen that.
- **Delivery index** — `history add-framework--roadmap` returns one `live` entry (2026-09-09, plan
  `2026-09-09T065116-PLAN--roadmap-command`). `history add-framework--backlog` resolves no node:
  nothing has ever shipped under the new name.

## Context & Motivation

After 001, 002 and 003, the product layer has a **backlog**: `docs/backlog.jsonl`, `backlog.sh`,
`add-backlog`. The internal layer has the same idea under the name **roadmap**, shipped in September
2026 and in daily use.

One idea, two words. Anyone reading both layers has to hold a translation in their head, and the
translation is the kind of thing that survives exactly as long as the person who learned it stays on
the project.

## Problem / Opportunity

The divergence is small and it is cheap to close **now**, while the product side is fresh and nothing
outside this repository depends on the internal name. It gets more expensive with every changelog and
every conversation that says "roadmap item N".

Two hazards the rename must not create:

1. **The item numbers are load-bearing.** Five months of changelogs, commit messages and index entries
   address the file's contents by number. A rename that renumbers anything invalidates all of it.
2. **The file cites its own history.** Item 1.2 tells the reader to run `git log docs/roadmap/index.md`
   to find the text of a removed item. After a rename that command returns the wrong answer unless the
   citation changes with it.

## Proposed Solution

A rename, and nothing else.

| From | To |
|---|---|
| `workbench/commands/add-framework--roadmap.md` | `workbench/commands/add-framework--backlog.md` |
| `workbench/provider-map.json` key `add-framework--roadmap` | key `add-framework--backlog`, description reworded |
| `docs/roadmap/index.md` | `docs/backlog/index.md` |
| node `internal/command/add-framework--roadmap` | `internal/command/add-framework--backlog` |

The file's **format, structure and item numbers do not change.** The word "roadmap" inside the command
and inside the file's own headings becomes "backlog"; every item keeps its number. The generated
`.claude/` and `.opencode/` copies are not touched by hand — `node scripts/build-workbench.js`
rewrites them.

### Alternatives considered

| Alternative | Why not |
|---|---|
| Also migrate the internal board to JSONL, so the two layers match in format as well as in name | The internal file is markdown that a human reads directly and that `/add-framework--plan` reads as text. Converting it is a migration of live content (items 1.2, 1.4, §5) that nothing has asked for, and it would make the file unreadable without a script in the one place where reading it raw is the normal way to use it. **The names match; the formats deliberately do not**, and that is recorded rather than left to be rediscovered |
| `docs/backlog.md`, flat, no directory | The command's whole text is written against a directory path, and a directory leaves room a single file does not. Changing the shape as well as the name is two changes wearing one label |
| Rename the command and leave `docs/roadmap/index.md` where it is | The command would write to a path named after the thing it is no longer called. The umbrella named both halves and they are one change |
| Rename the generated `.claude/commands/add-framework--roadmap.md` | It is gitignored build output, and `CLAUDE.md` forbids editing it in a stop block. Renaming it would be undone by the next build and would leave the real source untouched |
| Rewrite delivered changelogs that say "roadmap item 1.3" | They are the record of what was true when they were written. Editing history to match a later rename is worse than one stale word, and the item numbers still resolve |
| Leave the names different and document the mapping | The mapping lives in someone's head or in a table nobody opens. This is the divergence, not a fix for it |
| Fold the internal board into the product `add-backlog` skill and drop the internal command | Plan `2026-09-16T170340` already settled that `--roadmap` stays a standalone internal command. Reopening it is a different subtopic with a different objective |

## Scope

### Includes

- `git mv` on `workbench/commands/add-framework--roadmap.md` and on `docs/roadmap/index.md`, so
  history follows both renames.
- The `workbench/provider-map.json` key rename, and its `description` text, which says "roadmap" twice.
- Every occurrence of `roadmap` inside the command file, replaced with `backlog` — including the H1,
  the nine STEP titles, the stop blocks that name the owned path, the Conventional Commits scope, and
  the `ALWAYS — THIS COMMAND OWNS ONE FILE:` block.
- The `docs/backlog/index.md` H1, and **its two `git log` citations rewritten to `git log --follow`**,
  plus the header sentence that makes the same claim generically.
- The `CLAUDE.md` "Internal commands" row.
- `cli/tests/review-no-loops.test.js` L3.5 — the one assertion the rename breaks — in the same commit.
- The comment-only mentions in `close-out-hardening.test.js` and `build-artefact-graph.test.js`.
- One sentence in `framwork/.codeadd/skills/add-doc-schemas/references/backlog.md`, so a product file
  stops distinguishing the two layers by a word that no longer distinguishes them.
- `node scripts/build-workbench.js` run, so the generated `.claude/` and `.opencode/` copies follow.
- A grep sweep proving nothing live still names the old command or the old path.

### Does NOT Include

- Any change to what the command does. Nine steps in, nine steps out.
- Any change to the file's format, its item numbering, or its themes. Items 1.2, 1.4 and §5 come out
  the other side byte-identical except for the word "roadmap" in their own text and the `--follow` on
  their two `git log` citations.
- Migrating the internal board to JSONL. Weighed above and deliberately rejected.
- Hand-editing anything under `.claude/` or `.opencode/`. They are gitignored build output.
- `web/public/artefact-graph.mmd`. It is tracked but generated by `scripts/graph.js`; it changes when
  the build runs, not by hand.
- Delivered changelogs, delivery-index entries and archived plans that say "roadmap". They are the
  record.
- `workbench/agents/readme-analyzer.md` line 24 — read in context, it is about a `README.md` heading,
  not about this file.
- Any other product-layer file. The one sentence named above is the entire cross-layer surface.
- Re-opening whether the command should be a skill. Settled by plan `2026-09-16T170340`.

## Trade-offs & Risks

| We Gain | We Give Up |
|---|---|
| One word for one idea across both layers | Five months of changelogs and commit messages that say "roadmap", now slightly stale in wording |
| A rename done while it is cheap — zero graph dependants and one broken test | A muscle-memory command name, for whoever types it daily |
| The format divergence recorded as a decision rather than left as an accident | The appearance of a half-finished parity, until someone reads the reason |
| `git log --follow` stated where the file's own history is cited | A longer command in two places a reader copies |

| Risk | Probability | Mitigation |
|---|---|---|
| The rename is aimed at `.claude/` instead of `workbench/` | **Happened once already** — the first pass of this document did exactly that | Re-run Discovery against `origin/main`, which this pass did. Every path in this document is from the current tree, and the registry entry is named in Scope |
| A stale pointer survives in `CLAUDE.md` | High | Named as an explicit by-hand grep step, because no gate sees that file |
| `cli/tests/review-no-loops.test.js` L3.5 fails CI after the rename | **Certain, if not handled** | Updated in the same commit. Named here by file, line and test id so it cannot be discovered by a red build |
| The two `git log` citations keep the bare form and silently stop at the rename | Med | Rewritten to `--follow` as a scoped edit, with the measurement (2 commits versus 6) in Discovery so nobody has to take it on trust |
| `git mv` is done as delete-plus-create and the file's history is lost | Low | Stated as a decision. The file's own header points at `git log` as where removed items live, so the history is load-bearing |
| An item is silently renumbered while the file is being edited | Low | Nothing about item numbering changes. The plan's check is a diff showing only the H1, the word "roadmap", and the two `--follow` additions |
| Someone later "completes the parity" by converting the internal file to JSONL | Med | The rejection and its reason are a Key Decision and an explicit non-goal, in the document a future reader will open |
| `docs/backlog.jsonl` (product, a file) and `docs/backlog/` (internal, a directory) become siblings under `docs/` with the same name | Low | No filesystem conflict — one is a file, one is a directory, and they never coexist in one repository: `docs/backlog.jsonl` lives in a user's project, `docs/backlog/` in this one. Recorded so it reads as a decision rather than an oversight |
| The rename lands between 001–003 and confuses which layer a change belongs to | Low | 004 shares one sentence with them and touches the other layer otherwise. Delivered on its own branch, in any order |
