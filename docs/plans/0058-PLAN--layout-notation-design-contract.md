## Context

Two problems converge on `design.md`: the layout is authored as ASCII wireframes that the `feature-design` schema itself hard-bans (the most detailed layout information is thrown away at consolidation), and the document declares intent ("clear hierarchy") instead of values a reviewer can verify. This plan replaces ASCII with a schema-legal layout tree + component composition, adds the measurable `## Design Contract` section whose every dimension names its verification method, and requires the persisted QA spec to capture the computed-style values the contract names. The rendered-mock critique loop was evaluated and CUT (circular, tooling absent at plan time) — nothing here reintroduces it.

Post-0057 reality this plan builds on: the ASCII mandates no longer live in `add.design` (it is a thin dispatcher) — they live in the agent bodies (`ux-layout-agent` layout bullets, `ux-flow-agent` flow diagram) and in registry/table descriptions. The `## Design Contract` name is pre-referenced by `add.build.md:190` (0057) and MUST match exactly.

## Validated Decisions (carried from brainstorm 03)

Layout = minified JSON region tree (assertable, diffable, schema-compliant); composition tied to the real inventory; Mermaid flowchart branching-only; contract = markdown table (rules never JSON); every dimension names its verification method (vision models cannot measure px/contrast from downscaled PNGs); tap-target + contrast delegated to axe (no duplicate visual findings); computed-style capture converts "measure from image" into "compare two numbers"; contract inherits from design-context.md; **rendered mock loop stays CUT**; `expect` derives from the contract; unverifiable-never-passing.
